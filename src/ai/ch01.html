Part I · The new layer

What changed, and what did not

A language model is a new kind of component, one whose output no unit test can pin down, but most of what makes an AI service work in production is engineering you already know, applied to that component with care.

At a glance
  • The genuinely new part: the same input gives different outputs, any text that reaches the prompt can try to instruct the model, and every call has a price in tokens.
  • The familiar part: seams and adapters, timeouts, streaming, access control, observability, capacity, supply chain. All of it still applies, and most of an AI service is this.
  • Tests prove the code; evals measure the model and prompt together, as a pass rate over repeated runs.
  • A safety property that matters goes in code, not in the prompt: a prompt rule is a probability.
  • In the reference service, the AI-specific logic is a handful of modules: the prompt, the model seam, retrieval, redaction and the agent's tools. Everything around them is the standard platform.

The AI part is small

The reference service is an incident triage assistant: an on-call engineer asks about the alerts their teams can see, and a model answers from those alerts and the teams' runbooks, streaming its answer and citing the runbook sections it used. Its AI-specific logic lives in a handful of modules: the prompt builder, the seam that talks to any OpenAI-compatible endpoint, runbook retrieval, credential redaction and, in agent mode, the tool loop and its tools, about a third of the application code. Everything else (sign-in, roles, database isolation, rate limits, streaming, telemetry, deployment) is the same platform a service without a model would need, and that is deliberate: a new project replaces the domain and the prompt, and keeps the rest.

What is genuinely new

Tests and evals are different tools

A unit test proves the code does what it says. It cannot tell you whether answers stay grounded in the alerts, whether the model obeys instructions smuggled into alert text, or whether an answer mentions another team's incident. Those depend on the model and the prompt together, and the same case can pass twenty-nine runs and fail the thirtieth.

Safety in code, not in the prompt

A rule in a prompt is a probability. In the reference service, "never repeat credentials" still failed about one run in a hundred, and telling two wordings of that rule apart at such a rate takes thousands of runs. Redacting credentials in code before any model call cannot fail for the formats it recognizes, and keeps them from the provider too; the prompt rule stays as a second layer for formats the code does not know. The same principle bounds prompt injection: the prompt reduces the rate and evals measure it, but what limits the damage is architectural. The model has no tools that change anything, it is given only what the asker may read, and its output is rendered as text (Chapter 9).

Questions

  1. Name three things about a language model that are genuinely new to an experienced engineer, and three that are existing skills applied.

    Answer

    New: non-deterministic output measured as pass rates; untrusted text that can instruct the model; tokens as the unit of cost and latency (also: retrieval quality, judge calibration, reasoning tokens). Applied: a seam over the provider, timeouts and cancellation, streaming, access control over the context, observability, supply-chain and contract review.

  2. What can an eval tell you that a unit test cannot?

    Answer

    How often the model and prompt together behave as intended, such as staying grounded, refusing what the context does not support, resisting injected instructions and never crossing teams, as a pass rate over repeated runs with a real model.

  3. Why is a prompt rule not enough for a safety property?

    Answer

    It is followed with some probability, not always, and rare failures need thousands of runs to measure. Code (redaction, access-controlled context, no state-changing tools) enforces the property every time for the cases it covers.
