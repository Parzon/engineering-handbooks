Part VII · The data platform

Data engineering for AI

A model answers from whatever data arrived, so the data path to an AI feature needs the same discipline as the code path: contracts, quality checks, lineage, freshness targets, idempotent backfills, and evaluation data treated as data.

At a glance
  • At every step from the application database to an AI feature, data can arrive late, go missing, duplicate or change shape.
  • Batch or streaming is a freshness requirement, not a preference.
  • A data contract is an agreed, versioned schema with meanings and freshness, changed with the same expand-and-contract discipline as a database migration.
  • Re-embedding a corpus is a backfill: idempotent, in batches, built beside the old index.
  • Training and evaluation data must be point-in-time correct, computed the same way as at serving time, and kept apart from anything used for tuning.

Contracts, backfills and freshness

Two small data-engineering decisions in the reference service: a key that records how every vector was made, and the date shown to the model beside every section.

  • The embedding key names the model, the size and a hash of the document prefix; vectors with another key are ignored until a re-embed, because they are not comparable.
  • A prefix change alone moved every vector: measured, the same text with and without the prefix differed by 0.06 in distance.
  • Each section reaches the model with its team and its last update date, so a stale step is visible as stale.
def embedding_key(settings: Settings) -> str:
    """How vectors are made: the model, the size asked for, and a hash of the
    document prefix. Stored with every vector; vectors with another key are
    not comparable, so retrieval ignores them until they are re-embedded
    (`python -m app.cli reembed`). A prefix change alone moves every vector:
    measured, embeddinggemma with and without its prompts gave distances
    0.06 apart on the same text."""
    prefix = hashlib.sha256(settings.embedding_document_prefix.encode()).hexdigest()[:8]
    return f"{settings.embedding_model}|{settings.embedding_dimensions or 'native'}|{prefix}"
def section_text(number: int, hit: Hit, clean: Callable[[str], str]) -> str:
    """One runbook section as the model reads it, numbered for citation."""
    return (
        f"[R{number}] {hit.heading} (team {hit.team}, updated {hit.updated_at:%Y-%m-%d})\n"
        f"{clean(hit.content)}"
    )

Freshness is the age of the newest data, monitored like any service level. For retrieval it is the index lag: a runbook edited today but answered from last week's text. Lineage records which sources and transformations produced a table, so after a data incident it answers which answers, features or models used the bad data. Quality checks at each layer (not null, unique, accepted values, row counts against yesterday, references that resolve) stop the pipeline instead of passing bad data on.

Features, training and evaluation data

Personal-data rules (consent, minimization, deletion) apply to retrieval indexes, evaluation sets and training sets, not only to the source tables. A deleted document must leave the index, and a person's erased data must leave the evaluation sets built from production traffic.

How to say it

"Freshness is a requirement we set per use: a nightly re-index is fine for documentation, not for current incidents. We monitor index lag like any SLI."

"Backfills are idempotent and built beside the old data; a re-embedding is a backfill, because old and new vectors can't be mixed."

Questions

  1. When does an AI feature need streaming rather than batch data?

    Answer

    When its answers must reflect changes within seconds or minutes, such as an assistant answering about current incidents. Batch suits data whose freshness requirement is hours, such as a nightly re-index of documentation.

  2. What is training-serving skew, and what prevents it?

    Answer

    A feature computed one way for training and another for serving, so the model sees different numbers live. One definition of each feature, served to both, for example from a feature store.

  3. Why is re-embedding a corpus treated as a backfill?

    Answer

    Every vector must be recomputed, and old and new vectors are not comparable, so it runs idempotently in batches, builds the new index beside the old, is evaluated, and only then switched.
