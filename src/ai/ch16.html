Part VIII · Architecture and leadership

Stack defaults and the complexity dial

Complexity should follow measured pain, not anticipated pain, weighted by how expensive a choice is to reverse; so every stack starts from boring defaults and turns the dial (a cache, a queue, a split, a cluster, a vector database, an agent) only when evidence arrives.

At a glance
  • Default to the simple option; add complexity for a metric, an incident or a measured limit; experiment freely with choices that are cheap to undo.
  • Postgres for everything until a measured need it cannot meet; a cache beside it, never instead of it.
  • The fastest framework is the one the team already knows.
  • Compose, then a managed container platform, then Kubernetes only when many hosts or the organization's platform demand it.
  • Spend on latency and availability against a stated target; spending beyond it buys nothing measurable.

How to say it

"We add complexity for measured pain, weighted by how hard it is to reverse; anything we might need later goes into a decision record with the trigger that would justify it."

"Postgres does retrieval, isolation and audit; we'd add a vector database, a reranker or an agent only when a measurement or an eval shows the gap."

Questions

  1. What is the governing principle for adding complexity, and how does reversibility change it?

    Answer

    Add complexity for measured pain, not anticipated pain. Choices that are cheap to reverse can be tried early; choices that are expensive to reverse wait for evidence and are recorded as future options with a trigger.

  2. Name the three reasons that justify splitting a service out of a monolith.

    Answer

    A genuinely different scaling profile, a different deploy cadence, or a different failure domain.

  3. When would you add a reranker to a retrieval pipeline?

    Answer

    When retrieval metrics show the right chunk is found but ranked too low, for example because rank fusion weighs a confident wrong keyword match equally with the semantic winner, and the latency of a model on the critical path is acceptable.
