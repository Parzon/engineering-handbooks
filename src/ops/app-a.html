Terms used in this handbook, each with the chapter that explains it. Application terms are in Handbook 2's glossary; AI terms in Handbook 1's.

Application Load Balancer (ALB)
AWS's HTTP load balancer: terminates TLS, routes by path and host, and checks target health. Chapter 9
Artifact
A versioned output of the pipeline, such as an image, built once and promoted unchanged between environments. Chapter 3
Blue/green deployment
Running a second full environment on the new version and switching traffic at once, keeping the old one for a switch back. Chapter 13
Branch protection
Repository rules that require checks and reviews before anything reaches the main branch. Chapter 2
Canary
Sending a small share of traffic to a new version, watching it, and widening in steps. Chapter 13
CDK
The AWS Cloud Development Kit: infrastructure written in a programming language and synthesized to CloudFormation. Chapter 7
cloud-init
A tool that configures a new virtual machine on first boot from user data. Chapter 6
CloudFormation
AWS's native infrastructure-as-code service, which creates and updates stacks of resources. Chapter 7
Continuous delivery
Every change that passes the pipeline is releasable, and releasing is a routine, automated step. Chapter 3
Dependabot
GitHub's bot that opens pull requests to update dependencies and pinned images. Chapter 4
Drift
Differences between declared infrastructure and what actually runs, usually from manual changes. Chapter 7
ECR
Amazon Elastic Container Registry: private image storage in an AWS account. Chapter 5
ECS
Amazon Elastic Container Service: runs containers as tasks and services, on EC2 or on Fargate. Chapter 9
EKS
Amazon Elastic Kubernetes Service: managed Kubernetes control planes. Chapter 10
Environment
A separate copy of the system (development, staging, production) with its own configuration and data. Chapter 13
Fargate
Serverless compute for containers on AWS: no instances to manage. Chapter 9
Feature flag
A switch that turns code on or off per tenant or percentage without a deploy. Chapter 13
GitHub Actions
GitHub's CI/CD: workflows of jobs triggered by repository events. Chapter 3
gitleaks
A scanner for secrets committed to Git history. Chapter 4
IAM role
An AWS identity with permissions that a service, a task or a federated identity assumes temporarily. Chapter 5
Immutable infrastructure
Replacing servers or containers with new ones built from an image, rather than changing them in place. Chapter 6
Infrastructure as code (IaC)
Declaring infrastructure in reviewed, versioned code that a tool applies. Chapter 7
Kubernetes
A container orchestrator: pods, deployments and services scheduled across a cluster of nodes. Chapter 10
Least privilege
Granting each identity only the permissions its job needs. Chapter 5
NAT gateway
Lets resources in private subnets reach the internet without being reachable from it; priced per hour and per gigabyte. Chapter 8
OIDC federation
A CI job proves its identity to a cloud with a short-lived token and assumes a role: no stored keys. Chapter 5
Pinning
Referring to an action, image or dependency by an immutable identifier (a commit SHA, a digest) rather than a movable tag. Chapter 4
Pull request
A proposed change with its review, checks and discussion, merged into the main branch when approved. Chapter 2
Rollback
Returning to the previous known-good version; for code, redeploying the previous tag. Chapter 13
Rolling deployment
Replacing instances a few at a time, new ones healthy before old ones drain. Chapter 13
SBOM
A software bill of materials: the list of components inside an artifact. Chapter 3
Secrets Manager
AWS's store for secrets, which can generate, rotate and inject them at runtime. Chapter 5
Security group
A stateful AWS firewall attached to resources, allowing traffic by port and source. Chapter 8
Semantic versioning
MAJOR.MINOR.PATCH version numbers that signal breaking changes, features and fixes. Chapter 3
Subnet
A range of addresses in a VPC within one availability zone; public if routed to an internet gateway, private otherwise. Chapter 8
Supply chain
Everything that goes into an artifact (dependencies, base images, actions, the build itself) and can be attacked. Chapter 4
Tag (release)
A Git tag such as v1.2.3 that marks a release and, in the reference pipeline, triggers image publishing. Chapter 3
Task definition
ECS's description of a task's containers: images, CPU, memory, environment, secrets and roles. Chapter 9
Teardown
Deleting everything a stack created, in the order its dependencies require, and verifying nothing billable remains. Chapter 14
Trivy
A scanner for vulnerabilities in images, dependencies and configuration. Chapter 4
Trunk-based development
Short-lived branches merged often into one main branch, which stays releasable. Chapter 2
VPC
A virtual private cloud: an isolated network in an AWS account, divided into subnets. Chapter 8
VPC endpoint
A private connection from a VPC to an AWS service, avoiding the NAT gateway and the internet. Chapter 8
